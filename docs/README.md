# Docs

Start with the [project README](../README.md) for setup, configuration, the API list and test commands. Then:

| Doc | Read it to |
|---|---|
| [data-flow.md](data-flow.md) | See how data moves: practice, MCQ grading with Jev, Dashboard and Journey, `/admin`. Mostly diagrams |
| [backend-architecture.md](backend-architecture.md) | Learn the layers and their enforced rules, where new code goes, the module map, and each request path |

| [database-schema.md](database-schema.md) | See every table in an ER diagram, the content rules, and what a stored evaluation holds |
| [history.md](history.md) | Understand why things are shaped this way: the major changes and what they replaced |

The diagrams are Mermaid and render on GitHub and in most Markdown viewers.

Keep these docs current: a change that moves a module, adds a table or changes a request path updates the matching doc in the same commit.
